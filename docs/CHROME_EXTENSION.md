# Chrome 插件方案（方案 B）

本目录提供一个 **人工介入可恢复** 的 Chrome 扩展 MVP，目标是：

1. 在真实浏览器会话中批量采集 Google Trends `related queries`
2. 复用当前浏览器里的 Cookie / 验证状态
3. 支持 `API 模式`、`页面模式`、`混合模式`
4. 一旦遇到 Google 人机验证，立即暂停
5. 用户手动完成验证后点击“继续”，从当前关键词恢复
6. 最终导出中文 CSV

## 目录结构

```text
chrome-extension/
├── manifest.json
├── background.js
├── contentScript.js
├── popup.html
├── popup.css
└── popup.js
```

## 工作方式

- `popup.js`：负责输入关键词、选择抓取模式、启动任务、暂停/继续、导出结果
- `background.js`：负责维护任务状态、调度关键词队列、API 采集、页面模式切换、结果汇总
- `contentScript.js`：负责在真实 Trends 页面里读取相关查询卡片，并自动翻页采集

和 Python 版最大的不同是：

- 这里的请求发生在 **真实浏览器会话** 中
- 如果 Google 弹出验证码，用户可以在 **同一个浏览器上下文** 里手动完成
- 验证后再点击插件里的“验证后继续”，插件即可继续跑
- `API 模式` 默认点击“开始”后 **不会打开新标签页**
- `页面模式` 会打开并复用一个 Google Trends 标签页，并在页面里自动翻页采集
- `混合模式` 会先走 API；如果触发限流，当前及后续关键词会自动切到页面模式
- 插件弹窗会持续显示：状态、当前阶段、当前关键词、进度、最近结果
- 只有在 Google 要求人工验证时，插件才会自动打开验证页

## 使用方法

1. 打开 Chrome 的扩展管理页：`chrome://extensions`
2. 打开“开发者模式”
3. 点击“加载已解压的扩展程序”
4. 选择项目里的 `chrome-extension/` 目录
5. 点击插件图标，填写：
   - 关键词列表（一行一个）
   - 抓取模式：`API` / `页面` / `混合`
   - 时间范围，例如 `today 12-m` 或 `2026-03-06 2026-03-09`
   - 地区，例如 `CN`，留空表示全球
   - 每个关键词之间的最小/最大等待秒数
6. 点击“开始”
7. 采集过程中直接看插件弹窗：
   - `状态`：空闲 / 运行中 / 等待人工验证 / 已完成
   - `当前阶段`：例如“API 模式：请求 embed token”“页面模式：翻页采集”“等待下一个关键词”
   - `当前关键词`：当前正在处理或即将处理的关键词
   - `消息`：当前动作说明或错误信息

## 抓取模式说明

### API 模式

- 直接在浏览器会话里请求 Google Trends 接口
- 默认不打开新标签页
- 速度更快
- 但更容易先遇到 `429` 限流

### 页面模式

- 打开真实的 Google Trends 页面
- 通过内容脚本读取“相关查询”卡片
- 自动切换 `热门 / 上升`
- 自动点击 `Next` 翻页，直到拿完当前关键词的全部分页结果
- 可选开启 `AI 严格定位`，让模型在候选卡片里识别哪一块是“相关查询”

### 混合模式

- 先按 API 模式跑
- 一旦 API 触发限流，当前关键词与剩余关键词切到页面模式
- 最终结果仍统一汇总成一份 CSV

## 验证码流程

如果触发 Google 验证：

1. 插件状态会变成“等待人工验证”
2. 插件会自动打开一个验证页
3. 你手动完成验证码
4. 回到插件，点击“验证后继续”
5. 插件会从当前关键词继续请求

## 当前 MVP 范围

已支持：

- 批量关键词队列
- 浏览器会话内请求 `related queries`
- 页面模式自动翻页采集
- 混合模式在限流后自动切换页面模式
- 自动获取 `热门` 和 `上升` 两类结果
- 验证码暂停 / 手动继续
- 中文 CSV 导出
- 可选采集完成后自动下载 CSV

暂未做：

- 断点持久化到文件
- 邮件 / 微信通知
- 更细粒度的失败重试策略
- 复杂 UI（过滤、搜索、分组）

## CSV 导出

插件默认支持：

- 手动点击“导出 CSV”

插件额外支持：

- 勾选“采集完成后自动下载 CSV”
- 在限流或人工验证时，手动点击“结束本轮”

说明：

- 只有在本轮任务存在成功结果时才会自动下载
- 默认关闭，避免公开插件时未经用户明确同意就触发下载
- 如果你手动结束本轮，且当前已有成功结果，同时已开启自动下载，也会自动下载 CSV

## 重要说明

这个方案会比 `requests/trendspy` 更接近人工浏览器行为，但 **仍然不能保证永不触发风控**。

如果你开启了 `AI 严格定位`：

- 需要你自己填写 `OpenAI API Key`
- 支持配置自定义 `Base URL`，例如 `https://api.openai.com/v1`
- 这个 Key 只保存在本机浏览器扩展存储里
- AI 只用于页面里“哪张卡片是相关查询”的定位，不参与验证码处理
- AI 一旦没有明确选中“相关查询”卡片，当前关键词会直接失败，不再回退规则抓取
- 首次请求新的 Base URL 域名时，浏览器会申请该域名的网络访问权限

它解决的是：

- 人工验证后可以继续
- 同一浏览器会话内恢复更自然

它不能保证：

- 永远不出现验证码
- 长时间、高频、全自动批量采集仍然稳定
